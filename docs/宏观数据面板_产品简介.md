# 宏观数据面板 · 产品简介（AI Agent 版）

日期：2026-10-11
用途：给任何 AI Agent（编程、设计、评估）的自包含产品说明。读完本文即可理解产品全貌；工程细节以文档地图中的其他文档为准。

---

## 1. 一句话定位

一个**本地优先**的宏观经济与消费数据面板：Python 数据产品负责采集和加工中国宏观指标，Obsidian 插件负责在笔记软件内展示，服务零售商业地产从业者的月度经营判断。

## 2. 用户与场景

- **用户画像**：综合体购物中心总经理，同时关注全国大势与上海、四川/成都两个本地市场。具备宏观分析素养，但不是程序员。
- **使用节奏**：月度。每月 9–15 日官方数据陆续发布后，查看最新指标，撰写月度判断笔记。
- **决策场景**：业态配比（餐饮 vs 商品、服务 vs 实物）、招商与运营节奏、租户销售预警、项目投资判断。
- **关键诉求**：指标不只是"看看"，要服务**指征信号**——单一指标信号弱，多指标叠加（如社零与网上零售增速差、M1 与社零叠加）有交叉验证价值。

## 3. 产品形态：两个交付物

| 交付物 | 技术 | 职责 | 位置 |
|---|---|---|---|
| 数据产品（Python ETL） | Python + akshare（锁版本） | 采集、清洗、校验、生成标准化数据文件 | 独立仓库 |
| Obsidian 插件（TypeScript） | TypeScript + esbuild + ECharts | 只读渲染数据文件，展示面板 | 本仓库（`.obsidian/plugins/mcd`） |

**核心原则：插件只做展示——不采集、不判断、不联网。** 数据获取与加工全部封装在 ETL 侧；未来其他前端（Web、桌面）读同一套数据契约。

## 4. 数据流

```text
数据源（akshare/NBS/东财/手动录入）
  → ETL 定时抓取（Windows 任务计划程序 / macOS launchd）
  → data/raw/     原始快照，只追加，保证据可重跑
  → data/processed/  标准化指标序列 + manifest 总目录 + capabilities 能力声明
  → Obsidian 插件经 vault adapter 只读 <Vault>/MacroData/processed/ 渲染
```

## 5. 指标体系（看什么、为什么看）

**少而精，不盲目扩维度。** 三层结构：

| 层级 | 指标 | 用途 |
|---|---|---|
| 第一层：大势（全国） | 社零总额及同比、社零分项（限上 16 类）、餐饮 vs 商品增速差、网上零售额、服务零售额、M1/M2 及剪刀差、CPI/核心 CPI | 消费总盘子、品类结构、资金活化、需求真实温度 |
| 第一层（半自动/手动） | 住户存款、住户短贷/中长贷、可支配收入 | 居民防御心态 vs 消费意愿 |
| 第二层：本地（上海、四川/成都） | 本地社零及同比、本地餐饮增速 | 市场直接冷暖，与全国对比判断跑赢/跑输 |
| 第三层：辅助 | 城轨客运量（交通运输部）、上海金融数据（央行上海总部，季度）、机构季报（空置率/租金） | 城市活力旁证、行业周期 |

第一批实现（经接口验证门禁）：社零总额、社零分项与网上零售、M1/M2、CPI。省市社零滞后且日期不固定，采用窗口期轮询 + 超时转手动。

## 6. 界面结构（长什么样）

1. **总览仪表盘**：按层级分组的指标卡片——当前值 + 同比变化 + 24 个月迷你走势 + 数据期标注 + 新鲜度标记（fresh/临期/stale 三态标色）+ 新数据徽标。
2. **单指标详情页**：3–5 年长周期折线；工具栏切换视图状态：模式（日历序列/季节对比/同比序列）、图型（折线/柱状/面积/表格）、变换（原值/同比）、范围（1/3/5 年）、叠加指标。每个指标带一段"该指标对购物中心意味着什么"的解读文字。
3. **能力检测规则（产品灵魂）**：选项不可用时**置灰并显示原因**，不抛错、不阻断、不静默。统一文案模板：

   > 部分视图选项暂不可用：{选项名}。原因：{消息}。当前展示已支持数据。请检查指标注册表、日期范围、单位/频率，或等待下次 ETL 补齐。

   兜底回退：日历序列 + 折线 + 原值。
4. **发布日历与采集状态**（后续版本）：哪些数据已到、哪些轮询中、哪些待手动，失败不静默。

## 7. 核心数据规则（不可违背）

1. **只增不改**：数据入库后不修改；数据源修订时以递增 revision 版本追加，呈现层取最新版本。
2. **缺失存 null，不填 0**：图表断线，不跨缺失点连线。
3. **前端不算衍生指标**：yoy/mom/index 一律读 ETL 预生成的衍生序列；平滑、春节合并只是显示约定（不落盘，春节合并必须带文字说明）。
4. **不静默失败**：抓取失败在发布窗口内重试，超时标记并提醒手动处理；界面禁用项必须给出原因。
5. **双时间戳**：每条数据同时记录数据期（如 2026-08）与获取时间，呈现层标注时效。
6. **时区固定 Asia/Shanghai**。

## 8. 非目标（第一版不做）

内部数据交叉分析（数据结构已预留扩展位）、日度粒度数据（地铁日客流、日度 DR）、消费者信心指数等低时效指标、自动生成笔记草稿、行业机构报告结构化（季度手动摘录）、任何插件侧网络请求。

## 9. 技术速览

- **插件**：TypeScript（strict）+ esbuild 打包单文件 main.js + ECharts 图表 + jest 测试；只经 vault adapter 读 `<Vault>/MacroData/`，兼容 Obsidian 明暗主题，遵守 Obsidian 插件合规规范（不越 vault、零网络、注册即清理）。
- **ETL**：Python + akshare/curl_cffi（锁版本）；registry YAML 声明式驱动（每个指标一条配置：来源、口径、频率、新鲜度阈值、展示规格、信号组）；JSON Schema 校验一切产物；Windows 开发测试、macOS 运行验收。
- **数据契约**（前端唯一依赖）：`raw_snapshot_v1`（原始证据）、`indicator_series_v1`（标准化序列）、`manifest_v1`（总目录）、`capabilities_v1`（前端开关规则）。破坏性变更走 v2，不原地改。
- **开发方式**：编程 Agent（Qoder）+ Obsidian CLI 自动化闭环——构建/单测/冒烟/验收四层验证金字塔，对标 Android Studio 式全自动开发流程。

## 10. 关键术语表

| 术语 | 含义 |
|---|---|
| registry | 指标注册表（YAML）：指标定义与展示分离的唯一事实来源 |
| manifest | processed 目录总目录；前端先读它再读指标文件 |
| capabilities | 每个面板可用视图/叠加/变换的声明，附 supported/reason_code |
| reason_code | 不可用原因的标准码：历史不足/缺月/频率不同/地区不同/单位不一致/衍生序列缺失/源不支持 |
| view_state | 面板展示状态（指标/模式/图型/变换/范围/叠加），非数据契约 |
| freshness | 新鲜度三态：fresh/临期/stale，按注册表天数阈值判定 |
| signal | 指征信号，状态只有 support/conflict/insufficient；第一版只标记，不自动写笔记 |
| raw / processed | 原始快照层（保证据）/ 发布产物层（前端只读这里） |
