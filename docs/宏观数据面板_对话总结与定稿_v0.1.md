## 1. 已锁定决策

### 1.1 目标

建设一个本地优先的宏观/消费数据面板。  
第一版服务 Obsidian 插件展示。未来可服务 Web、桌面或其他前端。

核心原则：

- Obsidian 插件只做展示，不做采集，不做判断。
- 数据获取与加工封装为一个本地数据产品。
- 不同前端读同一数据契约。

### 1.2 运行形态

- ETL 跑在闲置电脑。
- Obsidian 与 ETL 同机。
- Windows 与 macOS 均可。核心 Python 代码平台无关。
- 平台差异只出现在调度、venv 激活、备份命令。

建议：

- 路径只用相对路径，用 `pathlib`。
- 时区固定 `Asia/Shanghai`。
- Windows 安装 `tzdata`。
- 写文件用 `*.tmp` 后原子 rename。
- 数据目录不入 Git。
- registry、schemas、etl、tests 入 Git。
- NBS 指纹不自己模拟，沿用 akshare / curl_cffi 会话，并锁版本。

### 1.3 修订策略

坚持：只增不改。

流程：

1. 每次抓取全量序列。
2. 与库内最新版本 diff。
3. 有变更才追加新版本。
4. 缺失存 `null`，不填 0。
5. 历史语义不原地改。口径变更走新 key 或 schema v2。

### 1.4 指标范围

不盲目扩维度。少而精。

已采纳新增：

- 网上零售额。
- 服务零售额。

待验证后再纳入：

- 核心 CPI。
- 东财社零总量接口。
- 东财货币供应接口。
- NBS 社零分项直连接口。
- 可支配收入接口。
- DR007 / FDR007 口径差异。

缺口维持手动或半自动：

- 住户存款、非金融企业存款。
- 住户短贷 / 中长贷。
- 省/市社零：上海、四川、成都。
- 城轨客运量。
- 上海金融数据。
- 机构季报 PDF。

### 1.5 akshare 门禁

结论：未验证前不直接写入 PRD 验收标准。

验证顺序：

1. 函数是否存在。
2. 返回列名是否稳定。
3. 数据起止日期。
4. 频率是否真实月度。
5. 单位是否稳定。
6. 是否修订。
7. 空值比例。
8. 连续缺月位置。
9. 触发风控或封禁情况。

### 1.6 指标注册表是核心

指标不是只展示。指标要服务“指征信号”。

设计原则：

- 单一指标信号弱。
- 多指标叠加有交叉验证价值。
- 信号第一版只做标记，不自动写笔记草稿。

信号状态统一：

```text
support / conflict / insufficient
```

## 3. 数据契约定稿

## 3.1 raw snapshot v1

用途：保留证据。支持重跑。不改历史。

文件路径：

```text
data/raw/YYYY-MM-DD/<source>_<key>.json
```

示例：

```json
{
  "schema_version": "raw_snapshot_v1",
  "key": "retail_sales_total",
  "source": "akshare",
  "endpoint": "macro_china_consumer_goods_retail",
  "params": {},
  "fetched_at": "2026-10-11T11:30:00+08:00",
  "timezone": "Asia/Shanghai",
  "payload_hash": "sha256:REPLACE",
  "records": [
    {"月份": "2026-09", "社会消费品零售总额": 411000, "同比增长": 3.8}
  ]
}
```

规则：

- `records` 保留原始列名。
- 不在 raw 层改口径。
- 解析与映射放 registry / etl。
- 同一 key 同一天可重复抓取，但 `payload_hash` 区分。

## 3.2 processed indicator_series_v1

用途：稳定数据产品契约。前端只读这里。

文件路径：

```text
data/processed/<key>.json
```

示例：

```json
{
  "schema_version": "indicator_series_v1",
  "key": "retail_sales_total",
  "title": "全国社会消费品零售总额同比",
  "region": "CN",
  "frequency": "monthly",
  "date_grain": "month",
  "timezone": "Asia/Shanghai",
  "unit": "yoy_pct",
  "null_policy": "null_not_zero",
  "status": "active",
  "source_refs": [
    {
      "source": "akshare",
      "endpoint": "macro_china_consumer_goods_retail",
      "raw": "data/raw/2026-10-11/akshare_retail_sales_total.json"
    }
  ],
  "series": [
    {"date": "2026-08", "value": 4.1, "revision": 1},
    {"date": "2026-09", "value": 3.8, "revision": 1}
  ],
  "quality": {
    "generated_at": "2026-10-11T11:31:00+08:00",
    "last_date": "2026-09",
    "point_count": 2,
    "missing_count": 0,
    "expected_frequency": "monthly"
  }
}
```

字段规则：

| 字段 | 必填 | 规则 |
|---|---:|---|
| schema_version | 是 | 固定 `indicator_series_v1`。破坏性变更升 v2。 |
| key | 是 | 稳定。不改名。 |
| region | 是 | `CN`、`SH`、`SC`、`CD` 等。 |
| frequency | 是 | `monthly`、`daily`、`quarterly`。 |
| date_grain | 是 | 月度用 `month`。 |
| unit | 是 | 如 `yoy_pct`、`mom_pct`、`index_2020_100`、`level_cny`。 |
| series[].date | 是 | 月度用 `YYYY-MM`。 |
| series[].value | 是 | number 或 null。 |
| series[].revision | 是 | 从 1 开始。修订追加新版本。 |
| quality.last_date | 是 | 最新非空日期。 |

## 3.4 capabilities v1

用途：控制前端开关。不抛错，只禁用或警告。

路径：

```text
data/processed/capabilities.json
```

示例：

```json
{
  "schema_version": "capabilities_v1",
  "generated_at": "2026-10-11T11:31:00+08:00",
  "panels": {
    "retail_sales_total": {
      "modes": {
        "calendar": {"supported": true},
        "seasonal_compare": {
          "supported": true,
          "warnings": ["2026-04 起数据缺失"],
          "reason_code": "MISSING_MONTHS"
        },
        "yoy": {"supported": true, "source": "retail_sales_total_yoy.json"}
      },
      "overlays": {
        "disposable_income_yoy": {"supported": true, "axis_mode": "single", "min_overlap_months": 36},
        "retail_sales_online_yoy": {"supported": false, "reason_code": "UNIT_MISMATCH"}
      },
      "chart_types": ["line", "bar", "area", "table"],
      "transforms": {
        "level": {"supported": true},
        "yoy": {"supported": true},
        "mom": {"supported": false, "reason_code": "DERIVED_NOT_FOUND"}
      }
    }
  }
}
```

reason_code 定稿：

| code | 含义 | 前端处理 |
|---|---|---|
| `INSUFFICIENT_HISTORY` | 历史长度不足 | 置灰 seasonal_compare。 |
| `MISSING_MONTHS` | 缺月 | 允许，但显示警告。 |
| `INCOMPATIBLE_FREQUENCY` | 频率不同 | 禁止叠加。 |
| `INCOMPATIBLE_REGION` | 地区口径不同 | 禁止或拆分双图。 |
| `UNIT_MISMATCH` | 单位不一致 | 默认禁止叠加；除非显式允许双轴。 |
| `DERIVED_NOT_FOUND` | 衍生序列未生成 | 禁用 transform。 |
| `SOURCE_UNSUPPORTED` | 数据源当前不支持 | 禁用相关选项。 |

提醒文案模板：

> 部分视图选项暂不可用：{option_name}。原因：{message}。当前展示已支持数据。请检查指标注册表、日期范围、单位/频率，或等待下次 ETL 补齐。

注意：

- 不静默禁用。
- 不阻断面板。
- 默认回退 `calendar + line + level`。
- 文案由 `reason_code` 映射，不写死在数据文件里。

## 5. 前端 view_state 定稿

面板状态不是数据契约。它只控制展示。

```json
{
  "indicator": "retail_sales_total",
  "mode": "calendar",
  "chart_type": "line",
  "transform": "level",
  "range": {"start": "2023-01", "end": "2026-03"},
  "overlays": ["disposable_income_yoy"]
}
```

前端规则：

- 不认识指标。只认识 `series / release / composite / signal_state`。
- 卡片由 `manifest + registry + capabilities` 动态生成。
- 不可用开关置灰，不抛错。
- 叠加默认单轴。单位不一致默认禁用，除非 capabilities 显式允许双轴。
- 切换 chart_type 若是纯展示，不动数据；若涉及 yoy/mom/index，读 processed 衍生序列，不临时乱算。

## 6. Windows / macOS 差异定稿

核心 Python：平台无关。

差异只放外壳：

| 项 | Windows | macOS |
|---|---|---|
| 调度 | 任务计划程序 | launchd 或 cron |
| venv 激活 | `venv\Scripts\activate` | `source venv/bin/activate` |
| 备份 | `robocopy` | `rsync` |
| 路径 | 禁止硬编码盘符 | 禁止硬编码用户目录 |
| 依赖锁 | `uv.lock` 或 `requirements.txt` | 同左 |

闲置机要求：

- 禁止睡眠。
- 接通电源。
- 自动登录或任务可运行。
- 失败重试。
- logs 轮转。
- 数据目录加杀毒白名单或排除项。

### 6.1 跨机流程：Windows 开发测试，macOS 运行验收

结论：可行。原则是：**开发机可以换，运行机必须做最终验收。**

流程：

1. Windows：开发代码、单元测试、schema 测试、registry 编辑。
2. macOS：安装锁定的依赖，跑真实抓取。
3. macOS：跑端到端测试。
4. macOS：配置 launchd 定时任务。
5. macOS：连续观察日志、失败重试、Obsidian 读取。

Windows 开发测试注意：

- 代码只用相对路径和 `pathlib`。
- 不写死 `C:\...`、`/Users/...`。
- 统一 UTF-8。
- `.gitattributes` 固定换行：
  ```gitattributes
  *.py text eol=lf
  *.yaml text eol=lf
  *.json text eol=lf
  *.sh text eol=lf
  *.bat text eol=crlf
  ```
- Python 版本与 macOS 一致。
- 用 `uv.lock` 或 `requirements.txt` 锁依赖。
- akshare、curl_cffi、pandas、pyyaml、tzdata 入锁。
- 单元测试可在 Windows 跑，但不得替代 macOS 端到端测试。

macOS 运行验收注意：

- 按运行机架构装依赖：Apple Silicon 用 arm64 环境，Intel 用 x86_64 环境。
- 首次执行：
  ```bash
  uv sync
  # 或
  pip install -r requirements.txt
  chmod +x run_etl.sh
  ```
- `run_etl.sh` 提交 Git 后保留可执行位：
  ```bash
  git update-index --chmod=+x run_etl.sh
  ```
- 用 `launchd` 调 `run_etl.sh`，不用 Windows 的 `.bat`。
- 数据目录不放 iCloud 同步路径。
- 验证 Obsidian 打开时读取 `processed` 正常。
- 验收四件事：
  1. 真实抓取能跑通。
  2. `processed` 与 `manifest` 正确生成。
  3. `capabilities` 禁用项只置灰，不抛错。
  4. 定时任务失败会写日志，可重试，不静默停跑。

机器相关配置只放本地 `.env` 或 config：

```text
VAULT_ROOT=...
SCHEDULER_NAME=...
BACKUP_TARGET=...
```

代码不猜机器，不写死路径。

### 7.2 etl/registry_io.py

```python
from pathlib import Path
import json

try:
    import yaml
except ImportError:  # 允许 registry 用 JSON，便于零依赖测试
    yaml = None

ROOT = Path(__file__).resolve().parents[1]


def load_registry() -> dict:
    p = ROOT / "registry" / "indicators.yaml"
    if p.exists():
        if yaml is None:
            raise RuntimeError("PyYAML is required for YAML registry.")
        return yaml.safe_load(p.read_text(encoding="utf-8"))
    p = ROOT / "registry" / "indicators.json"
    return json.loads(p.read_text(encoding="utf-8"))


def load_signals() -> dict:
    p = ROOT / "registry" / "signals.yaml"
    if p.exists():
        if yaml is None:
            raise RuntimeError("PyYAML is required for YAML registry.")
        return yaml.safe_load(p.read_text(encoding="utf-8"))
    p = ROOT / "registry" / "signals.json"
    return json.loads(p.read_text(encoding="utf-8"))
```

### 7.3 etl/export.py

```python
from pathlib import Path
import json
import os

ROOT = Path(__file__).resolve().parents[1]


def atomic_write_json(path: Path, obj: dict) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_suffix(path.suffix + ".tmp")
    tmp.write_text(
        json.dumps(obj, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
    os.replace(tmp, path)
```

def validate_processed(processed: dict) -> list[str]:
    errors = []
    if processed.get("schema_version") != "indicator_series_v1":
        errors.append("BAD_SCHEMA_VERSION")
    if not processed.get("key"):
        errors.append("MISSING_KEY")
    if processed.get("frequency") not in {"monthly", "quarterly", "daily"}:
        errors.append("BAD_FREQUENCY")
    for row in processed.get("series", []):
        if not row.get("date"):
            errors.append("MISSING_DATE")
        v = row.get("value")
        if v is not None and not isinstance(v, (int, float)):
            errors.append("BAD_VALUE_TYPE")
        if not isinstance(row.get("revision", 1), int):
            errors.append("BAD_REVISION")
    return errors

### 7.10 etl/core.py

```python
from datetime import datetime, timezone, timedelta
from importlib import import_module
from pathlib import Path

from .capabilities import build_capability
from .export import atomic_write_json, ROOT
from .fetchers.manual import SourceUnsupported
from .normalize import to_processed
from .registry_io import load_registry, load_signals
from .validate import validate_processed

CN_TZ = timezone(timedelta(hours=8))


def _call_fetcher(indicator: dict) -> dict:
    dotted = indicator.get("fetcher", "")
    if "." not in dotted:
        raise SourceUnsupported(f"bad fetcher path: {dotted}")
    mod_name, fn_name = dotted.rsplit(".", 1)
    mod = import_module(f"etl.fetchers.{mod_name}")
    fn = getattr(mod, fn_name)
    return fn(indicator)


def run() -> None:
    registry = load_registry()
    _ = load_signals()  # 第一版信号只加载，不展开自动笔记。
    processed_by_key: dict[str, dict] = {}

    for indicator in registry.get("indicators", []):
        if indicator.get("status") != "active":
            continue
        try:
            raw = _call_fetcher(indicator)
            processed = to_processed(indicator, raw)
            errors = validate_processed(processed)
            if errors:
                processed["quality"]["errors"] = errors
            atomic_write_json(ROOT / "data" / "processed" / f"{indicator['key']}.json", processed)
            processed_by_key[indicator["key"]] = processed
        except SourceUnsupported as e:
            # 不阻断整轮 ETL。记录日志。capabilities 标记 source unsupported。
            (ROOT / "logs").mkdir(exist_ok=True)
            with open(ROOT / "logs" / "etl.log", "a", encoding="utf-8") as f:
                f.write(f"{datetime.now(CN_TZ).isoformat()} SKIP {indicator['key']}: {e}\n")

    manifest = {
        "schema_version": "manifest_v1",
        "generated_at": datetime.now(CN_TZ).isoformat(),
        "timezone": "Asia/Shanghai",
        "indicators": [],
        "capabilities_file": "capabilities.json",
    }
    caps = {"schema_version": "capabilities_v1", "generated_at": manifest["generated_at"], "panels": {}}

    for indicator in registry.get("indicators", []):
        key = indicator["key"]
        p = processed_by_key.get(key)
        manifest["indicators"].append({
            "key": key,
            "file": f"{key}.json",
            "schema": "indicator_series_v1",
            "region": indicator.get("region", "CN"),
            "frequency": indicator.get("frequency", "monthly"),
            "unit": indicator.get("unit", "unknown"),
            "status": indicator.get("status", "planned"),
            "last_date": p.get("quality", {}).get("last_date") if p else None,
            "freshness": "unknown",
        })
        if p:
            caps["panels"][key] = build_capability(indicator, processed_by_key)
        else:
            caps["panels"][key] = {"source_supported": False, "reason_code": "SOURCE_UNSUPPORTED"}

    atomic_write_json(ROOT / "data" / "processed" / "manifest.json", manifest)
    atomic_write_json(ROOT / "data" / "processed" / "capabilities.json", caps)
```
