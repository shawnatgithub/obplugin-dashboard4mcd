# 宏观数据面板 · Agent 编程原则（D 系列）

日期：2026-10-11（自开发计划 v1.0 §6.5 拆分独立成册）
性质：**Agent 开发的原则性文件**，双仓（Python ETL 仓 + Obsidian 插件仓）通用，人类开发者与编程 Agent 一致遵守。
D1–D5 为用户定稿原则，D6–D10 为开发计划补充。

---

## 0. 优先级与适用范围

- 本文件是**过程性约束**：约束"怎么写代码、怎么报错、怎么验证"。产品与数据规则以 [v0.1 定稿](宏观数据面板_对话总结与定稿_v0.1.md) 为准，两者冲突时 v0.1 优先。
- 工作流程（验证金字塔、任务卡循环、Agent 边界）见 [Agent 自动化开发手册](宏观数据面板_Agent自动化开发手册.md)。
- 每次提交前，Agent 须对照 §2 自查清单逐条核对。

## 1. 原则正文

| ID | 原则 | 执行要点 |
|---|---|---|
| D1 | 写后必须回读验证 | 任何写入（数据产物、配置、生成代码）完成后必须回读并校验：JSON 反序列化 + schema 校验；ETL 落盘以 `atomic_write_json` 为唯一通道；fixtures 同步后校验和必须比对 |
| D2 | 失败必须恢复；回滚失败不得覆盖原始异常 | 带清理/回滚的写操作，若回滚自身抛错，必须保留原始异常（Python `raise X from e`；TS `new Error(msg, { cause })`）。限定适用面：事务性写路径；纯只读路径无回滚义务 |
| D3 | 区分"操作失败"与"环境不支持" | 网络超时、解析失败 = 操作失败：可重试，如实报错。依赖缺失、接口不存在、权限不足 = 环境不支持：走 `SOURCE_UNSUPPORTED` 类路径，置灰 + reason_code，不重试、不抛错阻断（对应 v0.1 §3.4 语义） |
| D4 | 注释写"为什么"，不复述"做了什么" | "做了什么"交给命名与结构；注释只保留口径依据（如"当月同比，非累计同比"）、外部接口的坑（如"NBS indicatorIds 须固定顺序做位置解析"）、不显然的设计取舍 |
| D5 | 错误报告保留完整因果链 | 错误信息必须包含：哪个 key、哪个阶段（fetch / normalize / validate / export）、原始错误、关键参数；禁止吞成 "failed"；日志一行一事件，可从错误行直接定位到 registry 条目 |
| D6 | 无失败测试，不修缺陷 | 修任何缺陷前，先写复现该缺陷的失败测试；修复后该测试转绿并永久留在套件中，防止"看起来修了" |
| D7 | 变更最小化 | 只做任务卡范围内的事；顺手重构、风格化改动、无关清理一律不做；发现无关问题记入 backlog，不扩大 diff |
| D8 | 单一事实来源 | 同一常量、映射、文案只在一处定义（reason_code 文案表、column_map、目录名等）；跨仓副本必须带来源与校验和（开发计划 G3 fixtures 即此原则的实例） |
| D9 | 可重入 | 插件 reload、ETL 整轮重跑、测试重复执行，结果一致且无泄漏：register* 全清理、只增不改、原子写；杜绝"跑第二次行为不同" |
| D10 | 显式声明，不隐式推断 | 不猜路径、不猜口径、不静默回退默认值；配置缺失就明确报错并指出缺什么（v0.1"代码不猜机器，不写死路径"的推广） |

## 2. 提交前自查清单（Agent 逐条核对，不满足不得声称完成）

- [ ] 所有写入产物已回读并通过 schema/校验和验证（D1）
- [ ] 本任务涉及的写路径：失败路径已恢复或明确上报；回滚异常未覆盖原始异常（D2）
- [ ] 错误分类正确：可重试的操作失败 vs 走置灰/`SOURCE_UNSUPPORTED` 的环境不支持（D3）
- [ ] 新增注释只解释"为什么"，无复述代码的冗余注释（D4）
- [ ] 新增/修改的错误信息含 key、阶段、原始错误、参数（D5）
- [ ] 若为缺陷修复：存在先失败后转绿的复现测试（D6）
- [ ] diff 只含任务卡范围内的变更（D7）
- [ ] 未引入同一常量/文案的第二处定义（D8）
- [ ] 插件 reload / ETL 重跑幂等，无监听器、定时器、临时文件泄漏（D9）
- [ ] 无猜测的路径、口径或静默默认值（D10）
