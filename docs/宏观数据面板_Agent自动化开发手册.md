# 宏观数据面板 · Agent 自动化开发手册

日期：2026-10-11（自开发计划 v1.0 §6 拆分独立成册）
性质：**Agent 工作流程标准**。任何编程 Agent（Qoder 等）在本项目开工前必读。
阅读顺序：[产品简介](宏观数据面板_产品简介.md) → **本手册** → [Agent 编程原则](宏观数据面板_Agent编程原则.md) → [UI/UX 设计指导](宏观数据面板_UI-UX设计指导.md)。任务来源：[开发计划 v1.0](宏观数据面板_开发计划_v1.0.md) §5（WBS）。

---

## 1. 目标

对标 Android Studio 的"Gradle 构建 → 模拟器 → 插桩测试 → 截图验收"全自动流程，实现编码、构建、测试、验收的 Agent 闭环：

| Android 流程 | 本项目对应 |
|---|---|
| Gradle assemble | `npm run build`（esbuild → main.js） |
| JUnit 单测 | `npm test`（jest + golden fixtures 契约测试） |
| 模拟器/ADB | **Obsidian CLI**（reload 插件、读控制台、截图） |
| 插桩测试/截图验收 | 冒烟脚本 + 视图切换验收清单（v0.1 §8.2） |

Python 轨（ETL 仓）同理：`pytest` 对应 JUnit，L2/L3 由产物 schema 校验与真实数据重放替代。

## 2. 验证金字塔（每个工作包完成前必须逐层通过）

```text
L0 静态门禁    npm run lint && npm run build        （含 tsc --noEmit）
L1 单元测试    npm test                              （契约测试用 tests/golden/）
L2 冒烟测试    Obsidian CLI：reload → 插件加载成功 → 控制台无错误 → 命令已注册
L3 验收测试    对照工作包 DoD 与 v0.1 §8.2 清单逐项核对（截图留证）
```

- 层级必须**自下而上**执行；任何一层失败，修复后**重跑该层及以上**（下层通过不代表上层免检）。
- 单测绿 ≠ 验收过：L2/L3 不可跳过（v0.1 §6.1："单元测试不得替代端到端测试"）。

## 3. 闭环执行协议（每个工作包一个循环）

1. **领取任务卡**：任务卡从开发计划 §5 的 WBS 派生（模板见 §5），不自行发明任务。
2. **编码**：遵守仓库根 `AGENTS.md` 全部规则（多文件组织、main.ts 最小化、register* 清理、无网络调用等）与 D 系列编程原则。
3. **L0→L1→L2→L3 逐层验证**，截图与验证输出附在提交说明。
4. **自检 DoD**：任务卡验收条目逐项核对后才可声称完成。
5. **提交**：常规 git commit；工作包全部 DoD 通过才标记完成。

失败处理：修复任何缺陷前，先写复现该缺陷的失败测试（D6）；修复后全层级重验。

## 4. Agent 边界（硬约束，违反即停）

- **不做产品决策**：遇 G/U 类事项（见开发计划 §3.2/§3.3）或 v0.1 未定义行为，停下询问用户，不得自行发明规则。
- **不改契约**：`schemas/`、`registry/`、`tests/golden/` 的任何变更须人工确认后执行（防止 Agent 为让测试通过而改契约）。
- **不越 vault**：插件代码只经 vault adapter 访问 `<Vault>/MacroData/`。
- **不引入网络**：插件侧零网络调用（v0.1：插件只做展示）。
- **不跳层**：L2/L3 不可跳过；不接受"单测已覆盖"作为免验理由。

## 5. 任务卡模板

```yaml
任务卡: <T编号>-<序号> <名称>            # 如 T3-3 总览仪表盘
目标: 一句话说明交付物
上下文:                                  # 只列真正需要的章节
  - 产品简介 §<节>
  - 开发计划 §5 T3-3、§3.2 G4
  - v0.1 §<节>
  - UI/UX 设计指导 §<节>
涉及文件: src/...                        # 预计改动面
DoD:                                     # 验收即命令
  - L0: npm run lint && npm run build
  - L1: npm test -- -t "<用例名>"
  - L2: node scripts/smoke.mjs           # reload + 控制台无错 + 命令注册
  - L3: <人工/Agent 逐项核对清单，截图留证>
禁止事项: 不改 schemas/registry/golden；不引入网络；不做任务卡外重构
```

## 6. 自动化基础设施（T3-9 / T2-6 交付物）

| 设施 | 说明 |
|---|---|
| `npm run verify` | 串联 L0+L1 的一键脚本 |
| 冒烟脚本（`scripts/smoke.mjs`） | 封装 Obsidian CLI 调用：reload、抓控制台错误、截图落 `artifacts/`；CLI 具体能力以实测为准，不足处降级为人工两步（M0 期间探明并固化） |
| 任务卡模板 | §5 的 YAML 模板 |
| `CLAUDE.md`/`AGENTS.md` 增补 | 把 §4 边界与 D 系列原则写入仓库，Agent 开工即读 |

## 7. 启动顺序（项目冷启动）

1. 用户确认/否决 G 类默认决策（尤其 G2 目录名、G6 图表库、G4 MVP 范围）。
2. 建 ETL 仓，落 v0.1 §2 目录树 + §7 骨架代码。
3. M0 启动：T1-1 → T1-2（验证报告）→ T1-3 → T1-4。
4. M0 门禁通过后，T2 轨（Python）与 T3 轨（插件）并行。
