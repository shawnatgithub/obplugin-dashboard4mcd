## 1. 产品概述与非目标

摘自 v0.1 §1 与确认稿：

- 本地优先的宏观/消费数据面板，第一版服务 Obsidian 插件展示。
- 插件只做展示；采集与加工由本地 Python 数据产品承担。
- 非目标（第一版不做）：内部数据交叉分析、日度粒度、低时效指标、自动写笔记草稿、行业报告结构化。

## 2. 系统架构与仓库拓扑

### 2.1 双交付物

| 交付物 | 仓库 | 内容 |
|---|---|---|
| 数据产品（Python ETL） | 独立仓库（G1） | v0.1 §2 的完整目录树：registry/ schemas/ etl/ data/ logs/ tests/ 及调度脚本 |
| Obsidian 插件（TypeScript） | 本仓库（`.obsidian/plugins/mcd`） | 只读消费 `processed/` 与 `signals/`，渲染面板 |

v0.1 §2 的仓库树本身就是数据产品仓（树中无 `src/`、无插件 manifest），独立建仓是对该架构的忠实执行，属 G1 默认决策。

### 2.2 数据目录（G2）

- v0.1 §6.1 的 `VAULT_ROOT` 配置已暗示 ETL 写入 vault。默认落位：`<Vault>/MacroData/`，即 ETL 仓的 `data/` 输出目录指向这里。
- 插件经 `this.app.vault.adapter` 读取 `<Vault>/MacroData/processed/`，符合 Obsidian"不越出 vault"的合规要求。
- 读写边界、Git 入库范围，完全沿用 v0.1 §2.1 表格。

### 2.3 契约缝合线（G3）

- 数据契约唯一权威定义在 ETL 仓 `schemas/`。
- 插件仓 `tests/golden/` 持有 fixtures 副本 + 校验和（SHA256 清单文件）；每次契约变更，由 ETL 仓重新导出并同步，插件侧 CI 校验和不过即失败，防止双仓漂移。

## 4. 里程碑计划

架构红利：**契约（M0）冻结后，Python 轨与插件轨可完全并行**，缝合线 = 数据契约 + golden fixtures。

| 里程碑 | 轨道 | 范围 | 退出标准（全部可命令验证） |
|---|---|---|---|
| **M0 契约与验证门禁** | 共同前置 | schemas JSON 定稿（四契约 + signal_state_v1，含 G9 补充字段）；fetcher 验证脚本（只出报告不入库）；四组指标验证（社零总额 / 社零分项·网上零售 / M1M2 / CPI）；golden fixtures 冻结；关闭 U1–U3 | 验证报告产出；schema 校验器对 fixtures 全绿；fixtures 冻结入两仓 |
| **M1 数据闭环** | Python | 真实 fetcher；raw 落盘 + payload_hash；revision diff 与追加；column_map 映射；manifest / capabilities 完整生成（v0.1 §8.3 全部 TODO）；logs 轮转 | 单测全绿；产物过 schema 校验；capabilities 禁用项含 reason_code |
| **M2 插件 MVP** | 插件 | settings + onboarding；manifest 驱动总览卡片；单指标详情（line/table + 新鲜度标注）；capabilities 置灰与提示文案（v0.1 模板）；默认回退 `calendar + line + level`；`npm run verify` 门禁脚本；Obsidian CLI 冒烟脚本 | 读 M1 真实产物渲染正确；禁用项零抛错；`npm run verify` 全绿 |
| **M3 分析交互** | 插件 | yoy 衍生序列消费；overlay（同频同单位单轴）；跨 region 拆分双图；平滑开关；春节合并显示；chart_type 切换 | v0.1 §8.2 七项全过 |
| **M4 运行与验收** | 共同 | 调度（任务计划程序 / launchd）；失败重试；手动 drop-folder（G5）；发布日历与采集状态 UI；macOS 端到端验收 | v0.1 §6.1 验收四件事全过；连续两周无人值守稳定运行 |
