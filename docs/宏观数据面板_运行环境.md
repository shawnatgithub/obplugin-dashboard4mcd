## 2. 双虚拟环境矩阵（G29）

两个环境各自独立锁定依赖，**不共用一份 requirements**——共用就等于放弃隔离。

| | 环境A | 环境B |
|---|---|---|
| 路径 | `D:\Codex\venv-pandas2` | `D:\Codex\venv-akshare` |
| 解释器 | Python 3.14.8（本机唯一） | 同左 |
| pandas | `2.3.3` | `3.0.6`（解析器决定，不设上界） |
| akshare | `1.19.1` | `1.19.1` |
| 锁定集 | `requirements-pandas2.txt` | `requirements-akshare.txt` |
| 角色 | AKShareWebapp 兼容区间；**M0 ETL 选定** | pandas 3 迁移候选 |

创建命令（两环境均在仓库与 vault 之外）：

```powershell
python -m venv D:\Codex\venv-pandas2
python -m venv D:\Codex\venv-akshare
```

bootstrap（每个环境装自己的锁定集，装前先过激活门禁确认身处哪个环境）：

```powershell
$env:PYTHONUTF8=1
D:\Codex\venv-pandas2\Scripts\python.exe  tools\assert_env.py D:\Codex\venv-pandas2
D:\Codex\venv-pandas2\Scripts\python.exe  -m pip install -r requirements-pandas2.txt
D:\Codex\venv-akshare\Scripts\python.exe  tools\assert_env.py D:\Codex\venv-akshare
D:\Codex\venv-akshare\Scripts\python.exe  -m pip install -r requirements-akshare.txt
```

两环境的包**永不交叉安装**；任何 `pip install` 之前必须先经 `assert_env.py` 确认。

## 3. M0 选定环境A 的依据（退出标准 #13）

双环境运行期冒烟（`tools/smoke_env.py`，各跑 `import akshare, pandas` + 一次真实抓取）：

- 环境A `pandas 2.3.3` → `SMOKE PASS via macro_australia_retail_rate_monthly rows=210`，exit `0`；
- 环境B `pandas 3.0.6` → `SMOKE PASS via macro_australia_retail_rate_monthly rows=210`，exit `0`。

按 spec §4.5 判定规则「两侧均 0 → 选 A」（pandas 2 生态更成熟，且是 AKShareWebapp 已在
运行的区间），选定**环境A**。本次无失败侧堆栈（两侧皆通过）；若未来某侧失败，须把失败
堆栈与原因补记于此并修订选定结论。

选定结果写入 ETL 仓 `.env` 的 `MCD_PYTHON`，此后所有入口只认这一个值（D8 单一事实源）：

```
MCD_PYTHON=D:\Codex\venv-pandas2\Scripts\python.exe
```

`MCD_PYTHON` 填**解释器绝对路径**（不是 venv 目录）。`run_etl.bat` 直接用它启动，
**不依赖 `activate`**，从根上消灭「忘了激活」这类错误（D10/G30）。

## 4. 激活门禁 assert_env.py（G30）

`tools/assert_env.py <expected-venv>` 打印 `executable/prefix/python/pandas/akshare`；
若 `sys.prefix` ≠ 期望路径则 **exit 1**，任务不启动。实测：

- 环境A 解释器 + 期望环境A → exit `0`；
- 环境B 解释器 + 期望环境A → exit `1`，并打印 `ENV MISMATCH` 与建议的解释器路径。

失败处置：不要混用两环境的包；按提示改用期望环境的解释器绝对路径重跑。`run_etl.py`、
`tools/validate_sources.py`、`tools/apply_verdicts.py` 与 pytest 入口均第一行调用它。

## 5. Windows 必须 PYTHONUTF8=1

pip / 脚本输出含中文时，默认 cp1252 会抛 `UnicodeEncodeError` 崩溃（实测，spec §16）。
所有 Windows 会话先设：

```powershell
$env:PYTHONUTF8=1
# 必要时再加 $env:PYTHONIOENCODING="utf-8"
```

ETL 仓内各入口脚本也已自行 `sys.stdout.reconfigure(encoding="utf-8")` 兜底（spec §7.9）。
